# בוט טלגרם לסטטוס קמפיינים ב-Roblox Ads

הבוט רץ כל 3 שעות ב-GitHub Actions, קורא את רשימת הקמפיינים שלך מ-Roblox Ads Manager ושולח סיכום בעברית לטלגרם.

## מה ההודעה כוללת

לכל קמפיין פעיל:

- שם הקמפיין, סטטוס ומצב הגשה: 🟢 SERVING, 🟡 IN_REVIEW, 🔴 REJECTED או NOT_SERVING, עם הסיבה
- תקציב בדולרים (יומי או כולל), וירידת תקציב מתוזמנת אם יש
- מה השתנה מאז הדיווח הקודם: סטטוס, הגשה, תקציב, קמפיין חדש

לכל משחק שקמפיין פעיל מקדם, ההודעה כוללת גם בלוק "📣 תנועה מפרסומות" מה-Analytics API, עם ארבעה מספרים מהיום האחרון ש-Roblox פרסמה (UTC), כל אחד עם השינוי מהיום שלפניו:

- 👁 ראו את המשחק בפרסומת (impressions)
- 🖱 לחצו ונכנסו לדף המשחק (clicks)
- 🎮 שיחקו (plays)
- 👥 משתמשים פעילים (DAU)

נספרים רק משתמשים שהגיעו דרך פרסומות, כלומר שמקור ההגעה שלהם (`AcquisitionSource`) הוא `SponsoredAds`, ‏`SearchAds` או `PortalAds`. ליד כל מספר מופיע גם הסך הכולל מכל המקורות, להשוואה.

חשוב לדעת:

- **משתמשים ייחודיים:** המספרים סופרים אנשים, לא פעמים. ב-Ads Manager סופרים חשיפות וכניסות, ולכן המספרים שם יהיו גבוהים יותר.
- **לפי משחק, לא לפי קמפיין:** אם כמה קמפיינים מקדמים את אותו משחק, המספרים שלהם מצטרפים יחד.
- **פעם ביום:** Roblox מעדכנת את הנתונים האלה פעם ביום, עם עיכוב של יום-יומיים, ולכן רוב הדוחות באותו יום יראו אותם מספרים.
- **הערכים של מקור ההגעה** לא מופיעים בתיעוד של Roblox. הם נלקחו ממה שה-API עצמו מחזיר.

אם ל-API key אין הרשאה לנתונים האלה, הבלוק מציג אזהרה ושאר הדוח נשלח כרגיל.

בסוף ההודעה יש סיכום של כל הקמפיינים ושעת הדיווח בשעון ישראל.
אם קמפיין עבר ל-REJECTED או ל-NOT_SERVING מאז הדיווח הקודם, מופיעה התראה 🚨 בראש ההודעה.

### מה ההודעה עדיין לא כוללת, ולמה

**הוצאה, אחוז ניצול תקציב, CTR ועלות לכניסה, וגם מדדים של קמפיין בודד, לא מופיעים.** הנתונים שלמעלה הם של כל הפרסומות למשחק יחד. נכון ל-9.11.2026, Roblox לא חושפת מדדי ביצועים של קמפיינים באף API שעובד עם API key:

- ה-Ads API מחזיר רק שם, סטטוס ותקציב.
- ב-Analytics API יש רק מדדי הכנסה מפרסומות שמוצגות בתוך המשחק שלך, ואין חיתוך לפי קמפיין.

Roblox הודיעה שהמדדים יגיעו דרך ה-Analytics API. הבוט כבר יודע להציג אותם ולחשב את השינוי בין דיווחים. כשהם יהיו זמינים צריך למלא פונקציה אחת, `fetch_campaign_metrics` בקובץ `roblox_ads_bot.py`, ולהוסיף ל-API key את ההרשאה שתידרש. עד אז, את המדדים רואים ב-[Ads Manager](https://create.roblox.com/docs/production/promotion/ads-manager).

### אילו קמפיינים מוצגים

מוצג כל קמפיין שהסטטוס שלו ACTIVE או שמצב ההגשה שלו SERVING. קמפיינים מושהים, מבוטלים או כאלה שהסתיימו (COMPLETED, EXPIRED, CANCELLED) לא מופיעים ברשימה, אבל נספרים בשורת "לא מוצגים". קמפיין שנעצר מקבל התראה פעם אחת, בדיווח הראשון אחרי שנעצר.

## התקנה, צעד אחרי צעד

### 1. יצירת API key ב-Creator Hub

1. היכנס ל-<https://create.roblox.com/dashboard/credentials?activeTab=ApiKeysTab> עם החשבון שמנהל את הקמפיינים.
2. לחץ **Create API Key** ותן לו שם, למשל `ads-telegram-bot`.
3. תחת **Access Permissions**, פתח את **Select API System** ובחר את מערכת הפרסום (Ads). השם המדויק בתפריט עשוי להשתנות, כי ה-API עדיין ניסיוני.
4. תחת **Select Operations** סמן **רק** את `ad.campaign:read`.
   אל תסמן `ad.campaign:write` או `ad.billing:read`. הבוט רק קורא, ו-key עם הרשאת כתיבה יכול ליצור קמפיינים ולהוציא כסף אם ידלוף.
5. לנתוני המשחק: הוסף מערכת נוספת, **universe-analytics**, וסמן בה רק את `universe.analytics:read`. תחת **Restrict by Experience** בחר את המשחק שאתה מפרסם. בלי השלב הזה הדוח עובד, אבל בלוק נתוני המשחק יציג אזהרה.
6. תחת **Security**, השאר את **Restrict IP addresses** כבוי. הכתובות של GitHub Actions משתנות, ולכן אי אפשר להגביל לפיהן.
7. אל תגדיר תאריך תפוגה, אחרת הבוט יפסיק לעבוד כשהוא יגיע.
8. לחץ **Save & Generate key** והעתק את המפתח מיד. הוא מוצג פעם אחת בלבד.

חשוב לדעת:

- ה-key חייב להיות של **משתמש**. בגרסה הנוכחית של ה-Ads API אין תמיכה ב-key של קבוצה.
- אם הקמפיינים שייכים לחשבון פרסום של **קבוצה**, ראה "קמפיינים של קבוצה" בהמשך.
- key שלא נעשה בו שימוש 60 יום פג אוטומטית. כל עוד הבוט רץ, זה לא יקרה.

### 2. יצירת בוט בטלגרם

1. פתח בטלגרם שיחה עם [@BotFather](https://t.me/BotFather). ודא שזה החשבון עם סימן האימות.
2. שלח `/newbot`.
3. בחר שם תצוגה, למשל `Roblox Ads Report`.
4. בחר שם משתמש שמסתיים ב-`bot`, למשל `my_roblox_ads_bot`.
5. BotFather יחזיר טוקן בצורה `1234567890:AAE...`. שמור אותו. מי שמחזיק בטוקן שולט בבוט.

### 3. מציאת ה-chat ID

1. פתח שיחה עם הבוט החדש ולחץ **Start**, או שלח לו הודעה כלשהי. בלי זה הבוט לא יכול לכתוב לך.
2. פתח בדפדפן את הכתובת הבאה, עם הטוקן שלך במקום `<TOKEN>`:

   ```
   https://api.telegram.org/bot<TOKEN>/getUpdates
   ```

3. חפש בתשובה `"chat":{"id":123456789`. המספר הזה הוא ה-chat ID.
4. אם התשובה היא `"result":[]`, שלח לבוט עוד הודעה ורענן את הדף.

כדי לקבל את הדוח בקבוצה, הוסף את הבוט לקבוצה, שלח בה הודעה וחזור על שלב 2. ה-ID של קבוצה הוא מספר שלילי.

**שליחה לכמה צ'אטים:** כתוב את כל ה-IDs באותו ערך, מופרדים בפסיק, למשל `911893965,5460050858`. כל צ'אט חייב ללחוץ **Start** בבוט לפני ההודעה הראשונה, אחרת טלגרם חוסמת את השליחה אליו. אם צ'אט אחד נכשל, השאר עדיין מקבלים את הדוח, והריצה מסומנת ככושלת ב-GitHub כדי שתשים לב.

### 4. העלאה ל-GitHub והפעלה

1. צור ריפו חדש ב-<https://github.com/new> ובחר **Private**. קובץ המצב שהבוט שומר מכיל שמות קמפיינים ותקציבים, ובריפו ציבורי כולם יראו אותם.
2. העלה את כל הקבצים, כולל התיקייה `.github`. מתוך תיקיית הפרויקט:

   ```bash
   git init
   git add .
   git commit -m "Roblox Ads Telegram bot"
   git branch -M main
   git remote add origin https://github.com/<USER>/<REPO>.git
   git push -u origin main
   ```

   לפני ה-push ודא שהקובץ `.env` לא ברשימה של `git status`. הוא אמור להיות מוסתר על ידי `.gitignore`.
3. בריפו, עבור אל **Settings → Secrets and variables → Actions → New repository secret** והוסף שלושה secrets, בדיוק בשמות האלה:

   | שם | ערך |
   |---|---|
   | `ROBLOX_API_KEY` | המפתח מצעד 1 |
   | `TELEGRAM_BOT_TOKEN` | הטוקן מצעד 2 |
   | `TELEGRAM_CHAT_ID` | המספר מצעד 3. לכמה צ'אטים: מופרדים בפסיק |

4. עבור ללשונית **Actions**, בחר **Roblox Ads report** ולחץ **Run workflow**. להרצת ניסיון שלא שולחת כלום, סמן את התיבה של dry run, וההודעה תודפס בלוג.
5. אם הכול תקין, תגיע הודעה בטלגרם תוך כדקה. מכאן הבוט רץ לבד כל 3 שעות.

אם ה-push של קובץ המצב נכשל עם שגיאת הרשאה, עבור אל **Settings → Actions → General → Workflow permissions** ובחר **Read and write permissions**.

### 5. הרצה מקומית לבדיקה

דרוש Python 3.11 ומעלה. ב-Windows אפשר לכתוב `py` במקום `python`.

```bash
pip install -r requirements.txt
```

בדיקת העיצוב עם נתוני דמה, בלי מפתחות ובלי לשלוח כלום:

```bash
python roblox_ads_bot.py --demo --dry-run
```

אותו דבר עם מדדי ביצועים בדויים, כדי לראות איך ההודעה תיראה כשהמדדים יהיו זמינים:

```bash
python roblox_ads_bot.py --demo-metrics --dry-run
```

להרצה מול החשבון האמיתי, העתק את `.env.example` לקובץ בשם `.env`, מלא בו את שלושת הערכים, ואז:

```bash
python roblox_ads_bot.py --dry-run
```

הפקודה הזו קוראת מ-Roblox ומדפיסה את ההודעה למסך. היא לא שולחת לטלגרם ולא שומרת מצב. בלי `--dry-run` ההודעה נשלחת והמצב נשמר.

כדי לבדוק רק את החיבור לטלגרם, בלי Roblox:

```bash
python roblox_ads_bot.py --demo
```

הרצת הבדיקות האוטומטיות:

```bash
python -m unittest discover -s tests -v
```

## איך זה עובד

### שמירת מצב בין ריצות

כדי לדעת מה השתנה, הבוט שומר אחרי כל דיווח את הקובץ `state/snapshot.json`, וה-workflow עושה לו commit חזרה לריפו.

נבחר commit ולא `actions/cache`, משלוש סיבות:

- ב-cache אי אפשר לעדכן מפתח קיים, ולכן כל ריצה הייתה צריכה ליצור מפתח חדש.
- GitHub רשאית למחוק cache בכל רגע, ומוחקת cache שלא נגעו בו 7 ימים. מחיקה כזו הייתה מעלימה התראה בלי שתדע.
- ב-commit המצב נשמר תמיד, ומתקבלת היסטוריה של כל שינוי שאפשר לעיין בה.

המחיר הוא commit קטן בכל ריצה, כלומר כ-8 ביום.

המצב נשמר רק אחרי שההודעה נשלחה בהצלחה. אם השליחה נכשלת, הריצה הבאה תשווה שוב מול אותו מצב, וההתראה לא תאבד.

### שגיאות

- תשובות 429 ו-5xx ושגיאות רשת מקבלות עד 5 ניסיונות עם המתנה שהולכת וגדלה (2, 4, 8 ו-16 שניות). אם השרת שולח `Retry-After`, הבוט מכבד אותו.
- אם הקריאה ל-Roblox נכשלת בסוף, נשלחת לטלגרם הודעת שגיאה קצרה עם קוד השגיאה, והריצה מסומנת ככושלת ב-GitHub.
- הודעה ארוכה מ-4096 תווים מפוצלת לכמה הודעות, והחיתוך נעשה בין קמפיינים.

### קמפיינים של קבוצה

אם הקמפיינים שייכים לחשבון פרסום של קבוצה, הוסף את מזהה הקבוצה:

- ב-GitHub: **Settings → Secrets and variables → Actions → Variables → New repository variable** בשם `ROBLOX_GROUP_ID`.
- מקומית: שורה `ROBLOX_GROUP_ID=...` בקובץ `.env`.

ה-key עדיין צריך להיות של משתמש שיש לו הרשאה לנהל את הפרסום של הקבוצה. המסלול הזה לא נבדק מול חשבון אמיתי.

### שינוי התזמון

התזמון מוגדר בקובץ `.github/workflows/ads-report.yml`, בשורה `cron: "0 */3 * * *"`. השעות הן ב-UTC, ו-GitHub עשויה להתחיל ריצה באיחור של כמה דקות בשעות עמוסות.

## מגבלות שכדאי להכיר

- ה-Ads API של Roblox מוגדר ניסיוני, ו-Roblox ממליצה לא לבנות עליו אוטומציה קריטית. אם מבנה התשובות ישתנה, הבוט ישלח הודעת שגיאה ויהיה צריך לעדכן אותו.
- הבוט נבדק עם נתוני דמה ועם שרת מדומה. הוא עדיין לא הורץ מול חשבון Roblox אמיתי.
- בריפו פרטי, GitHub Actions נותן 2,000 דקות חינם בחודש. הבוט צורך כ-250.
- אם תחליף API key או טוקן, עדכן את ה-secret המתאים ב-GitHub. אין צורך לשנות קוד.
